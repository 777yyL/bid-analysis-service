# 每日分析工作台实施计划

> 执行方式：当前会话按步骤实施，沿用已确认原型；不创建提交，不覆盖已有修改。

**Goal:** 将已确认的 `designs/daily-workbench/index.html` 适配到真实服务，统计可下钻、结论可核对。
**Architecture:** React 页面沿用现有组件；每日数据读取主库 `notices` 的首次入库日期，按项目归集，与分析结果及任务关联。新增显式同库部署模式，独立 schema 保存结果，不复制来源表。旧部署保留兼容入口及数据，不执行删除或自动迁移。
**Tech Stack:** React / TypeScript、FastAPI、SQLAlchemy、PostgreSQL。
**Spec:** 本会话已确认四入口设计及 `designs/daily-workbench/` 原型。

## Constraints
- 不用演示数据填充正式页面；主库不可用时明确报错。
- 手动刷新，无列表轮询；后端分页，当前有效且启用的 confirmed 标签才算命中。
- 北京时间入库日和公告发布时间分开；缺阶段、缺主公告和待提取不算未命中。
- 保留已完成分析和标签；同库模式不创建或消费来源同步、文件下载任务。
- 新增同库模式由部署配置启用；不擅自操作当前数据库或切换现有部署。

## Review focus
- 新公告属于已有项目：新增公告数与新项目数不能混算。
- 同项目多标段、多轮次及更正：复用既有选择器，不能只看最新公告。
- 待提取或失败：无标签不等于已分析未命中。
- 相同项目强制重算时仍有旧有效标签：进度和命中是独立维度。
- 日期、数据源、分页切换的异步响应：取消旧请求；统计和下钻使用同一筛选口径。
