# 售前 100 问 MCP 验收

2026-11-18 测试仓库版本 0.8.20。100 道不同的售前问题，固定工具路线，实际启动 FastAPI/Uvicorn，通过官方 MCP 客户端和 Streamable HTTP 访问独立 PostgreSQL 13。原配置的内网地址 TCP 连接超时。数据、结论命中率与耗时仅用于本地功能验收。本次没有运行 WorkBuddy 的自然语言选工具或最终答复环节。

测试结束日期固定为 2026-11-16，默认窗口包含当日及前六天。5 份公告、4 个项目、2 个已匹配项目。有一条北京项目的已存阶段与主库最新阶段不同，两个项目（武汉、北京）使用同一个合成采购单位。近期未匹配/待复核等筛选的正确空集计为可回答，不能据此证明该状态的正例质量。

总计 104 次业务工具调用。66 道符合预设答案，2 道提供部分信息，14 道返回内容未满足验收条件，18 道能力探测参数被接口校验拒绝。每题请求累计延迟中位数 13.73 ms，P95 20.17 ms。串行调用，排除启动和工具发现时间。

## 优化优先级

1. **跟进状态与证据卡。** 第 41、42 题返回的项目阶段不一致。机会清单按主库当前阶段和有效撤销状态筛选，并保留分析时阶段。优先展示采购人、需求摘录、证据、可访问的公告链接。截止日期、预算只取可信字段并标注来源，缺失时显示未知。第 43–46、100 题可用于验收。

2. **客户归集。** 第 51–60 题均无法完整回答。先提供采购人字段和按标准客户键筛选/聚合，按独立项目去重，给出最近需求和代表项目。代理机构、未知采购人、同名未核实的单位单列。

3. **区域与能力发现。** 第 3、91、92 题验证市级编码精确匹配、省级查询及中文地区名的差异。第 93、94 题验证别称和采购需求全文对当前名称/标题查询的影响。建议返回实际解析的地区范围与销售项，明确检索域。

4. **季度和新增分析。** 对第 71–75、80 题开放服务端按月和长周期去重汇总，先验证真实数据执行计划。第 78、79 题另需标签首次生效及确认事件时间。对于主库整体覆盖率（88、89），若开放，应单列全量分母。

18 道接口限制测试故意尝试用户意图所需的参数，检验单次调用能否表达该业务问题。多周统计有的可以分段、分页取回项目键后再去重。因而“接口限制”不能解读为任何客户端都无法组合求解。带 @ 的检查要求返回结构化字段，不是对任意正文做语义抽取。

## 复跑

本地固定答案模式：在仓库安装测试依赖，配置 BID_MCP_TEST_DSN 指向允许创建临时库的专用测试 PostgreSQL，运行 python tests/run_presales_mcp_fixture.py。脚本生成独立临时数据库，测试完清理该临时库。

内网只读模式：在含 Python 依赖的环境运行下面命令，MCP_API_KEY 从环境读取。将日期、项目键和销售项 ID 换成现场数据。第二个项目用于核查阶段，第二个销售项用于对比确认来源。题库的地区、客户名和分类可按现场情况编辑 TSV。现场模式记录接口限制与返回字段，真实答案需要结合主库核对。

```text
python scripts/evaluate_presales_mcp.py --url http://127.0.0.1:8100/mcp/ --end 2026-11-16 --project 主项目键 --second-project 阶段已变化的项目键 --item 主销售项ID --second-item 第二销售项ID --output presales-live.json
```
